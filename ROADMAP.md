# RunSteward roadmap

The current candidate preserves and organizes existing capabilities. The items below are durable
outward gates or later work, not claims that a capability is presently live.

## Before activation

- Host-backed CI proof from the exact release candidate.
- Explicit lifecycle-authority decision for any install, exposure, activation, promotion, or
  predecessor supersession.
- Explicit owner decision for predecessor privacy or archive actions after successor parity is
  accepted.

## Later capability work

- Add live provider surfaces only when their evidence can be typed without converting incomparable
  metrics or weakening approval gates.
- Extend qualification matrices when new runtime capabilities exist; do not represent qualification
  tooling as runtime behavior.
- Add host-aware ReleaseBench audits and release automation behind exact outward-action gates.
- Revisit package and source distribution boundaries if bundled products receive separately
  approved public-safe successors.

None of these items authorizes a provider call, remote write, live-skill change, publication,
predecessor archive, bundled-package edit, history rewrite, or destructive cleanup.
